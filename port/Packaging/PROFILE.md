# Supported native profile —0.1.0-u62

This unsigned local source recompilation preserves ordinary MVC developer shapes while using native .NET10 hosting, routing, authentication and protection. It is not an official Microsoft distribution, signed Framework replacement, general System.Web emulator or production-readiness certification. Source compatibility, binary/type identity, wire/token formats and runtime behavior are separate claims. The tested sample is Stockroom; accepted earlier combined-consumer evidence remains valid within its contracts.

The protected boundary is the public MVC application contract. Native .NET 10 may replace internal implementation freely; source identity and historical internal semantics are not preservation requirements. The agreed native port is assessed against the fourteen documented groups with explicit native differences, not an absent-type count or historical Framework/IIS/binary/wire parity. See [operations](OPERATIONS.md) and [provenance](PROVENANCE.md).

## Finite compatibility disposition

Implemented native behavior is backed by bounded contracts and observed workflows; configuration responsibilities are concrete shipped code/settings, not missing MVC machinery. Deployment operators own identity lifecycle, certificates, protected ring access/rotation, proxy ingress and durable storage operations. Those operations remain untested here and receive no behavior credit. Original unobtrusive validation/Ajax is implemented and independently reviewed for this bounded native release profile.

Sixteen released MVC type names are absent. Four legacy integration shapes (`MvcHandler`, `MvcHttpHandler`, `PreApplicationStartCode`, `MvcWebRazorHostFactory`) have native endpoint/startup/build-time Razor replacements. Eleven belong to the intentionally omitted WebForms page/control/view-engine platform. The remaining `LinqBinaryModelBinder` is not needed for the approved native model choice: use `byte[]` and the existing original `ByteArrayModelBinder`. Native `HiddenFor(byte[])` output round-trips through prepared form input and original action/model binding.

The standalone Microsoft `System.Data.Linq.Binary` class already exists for earlier helper compatibility; the absence of its historical binder does not mean the class is missing. Migrate application models from `Binary` to native `byte[]`; no LINQ-to-SQL query/mapping/database provider is supplied or required. Native hosting, explicit startup, C# Razor and native authentication/protection replace the approved historical platform dependencies. These are explicit scope decisions, not unfinished native framework machinery. A complete native port is not an interchangeable signed Framework binary or production deployment certification.

Client coverage is bounded to original MVC scripts with jQuery3.7.1/Validation1.22.1: field/summary suppression, required/number/range, isolated length/equal-to/remote, dynamic parsing, Ajax form/link callbacks/update modes/cancellation/failure, and root/nested native security. Non-JS server validation/redirect/TempData and separate fetch are retained. This closes the identified client implementation gap with independent PASS; no claim of all plugin adapters, locales, browsers or arbitrary CSP callback expressions follows.
